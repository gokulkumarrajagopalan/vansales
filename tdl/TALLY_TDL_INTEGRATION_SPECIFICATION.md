# Talliffy Van Sales ERP — TallyPrime TDL Developer Integration Specification

**Document Version:** 2.4.0  
**Target Audience:** Tally TDL Developers, Integration Engineers & System Integrators  
**Compatible Systems:** TallyPrime (1.0 to 4.x), Tally.ERP 9  
**Server Environment:** Production Gateway  
**Base URL (IP):** `http://66.116.232.161:8088`  
**Base URL (Domain):** `https://vansales.talliffy.com`  

---

## 1. Overview & Architecture

Talliffy Van Sales ERP manages mobile van inventory, on-the-road sales invoices, cash collections, and stock transfers. This document provides the complete technical contract for the TDL developer to build the Tally connector script to:

1. **Pull Sales Invoices & Receipts** generated by vans into TallyPrime.
2. **Synchronize Master Data** (Parties/Sundry Debtors, Stock Catalog, and Van Godowns) bidirectionally.
3. **Acknowledge Imports** to mark vouchers as synced and prevent duplicate entry.

```
+-------------------------------------------------------------------+
|                        Talliffy Cloud ERP                         |
|   (PostgreSQL + Node.js API Gateway at http://66.116.232.161)     |
+---------------------------------+---------------------------------+
                                  |
                                  | HTTP / JSON or XML
                                  | Authorization: Bearer <JWT_TOKEN>
                                  v
+---------------------------------+---------------------------------+
|              TallyPrime / TDL Connector Gateway                   |
|        - TDL Native Functions ($$HTTPPost / $$HTTPGet)            |
|        - Or External Node.js / Python Auto-Sync Daemon            |
+---------------------------------+---------------------------------+
                                  |
                                  v
+---------------------------------+---------------------------------+
|                       Tally Company Books                         |
|   (DayBook: Sales Vouchers, Receipts, Godowns, Debtors, Stock)    |
+-------------------------------------------------------------------+
```

## 2. Authentication & JWT Token Flow

Every request to data endpoints requires a standard **JSON Web Token (JWT)** passed in the `Authorization` HTTP header.

### Method 1: Dedicated Tally Connector Authentication (Recommended for TDL)

* **Endpoint:** `POST /api/tally/Auth`
* **Content-Type:** `application/json`
* **Authentication Required:** No (Public handshake)

#### Request Payload:
```json
{
  "userId": "tally_connector",
  "password": "StrongPassword123!",
  "apiKey": "VB-API-KEY-998877"
}
```

#### Response (HTTP 200 OK):
```json
{
  "isValid": true,
  "message": "Authenticated successfully",
  "errorCode": null,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VySWQiOjAsInVzZXJuYW1lIjoidGFsbHlfY29ubmVjdG9yIiwicm9sZSI6IlRBTExZX0NPTk5FQ1RPUiIsImNvbXBhbnlJZCI6MTIsImlhdCI6MTc5NTI0Njk3MCwiZXhwIjoxNzk1MjUwNTcwfQ.4r27qvCYazBNkUhJnIWPP_Ax_LcelN6z6DBDa82rgkg",
    "expiresInSeconds": 3600,
    "tokenType": "Bearer"
  }
}
```

#### Response Fields:
| Field | Type | Description |
| :--- | :--- | :--- |
| `isValid` | Boolean | `true` if authentication succeeded, `false` otherwise. |
| `data.token` | String | **The JWT Bearer token** to store and use for all subsequent calls. |
| `data.tokenType` | String | Always `"Bearer"`. |
| `data.expiresInSeconds` | Number | Token lifespan (3600 seconds = 1 hour). Re-authenticate when expired. |

## 3. Pulling Data into Tally (Talliffy -> TallyPrime)

### 3.1 Pull Sales Invoices (`POST /api/tally/SalesVouchers`)

Retrieves finalized van sales invoices ready for booking into Tally Sales DayBook.

* **Endpoint:** `POST /api/tally/SalesVouchers`
* **Headers:**
  - `Content-Type: application/json`
  - `Authorization: Bearer <TOKEN>`

#### Request Payload (Filter Parameters):
```json
{
  "fromDate": "2026-11-01",
  "toDate": "2026-11-30",
  "voucherStatus": "READY"
}
```
*Note: If payload is `{}` (empty object), it returns all vouchers.*

#### Response Payload (HTTP 200 OK):
```json
{
  "isValid": true,
  "message": "Sales vouchers retrieved successfully",
  "errorCode": null,
  "data": {
    "totalRecords": 1,
    "vouchers": [
      {
        "guid": "MOB-1-1794591874716",
        "voucherNumber": "INV-1002",
        "voucherDate": "2026-11-14T00:00:00.000Z",
        "voucherType": "Sales",
        "partyLedgerName": "West Zone Fresh Supermarket",
        "narration": "Van Sales Invoice INV-1002 - Driver: Karthik Rao",
        "grossAmount": 72.00,
        "taxAmount": 3.60,
        "roundOffAmount": 0.00,
        "netAmount": 75.60,
        "ledgerEntries": [
          {
            "ledgerName": "West Zone Fresh Supermarket",
            "entryType": "DEBIT",
            "amount": 75.60,
            "isParty": true
          },
          {
            "ledgerName": "Sales Account - Van 01",
            "entryType": "CREDIT",
            "amount": 72.00,
            "isParty": false
          },
          {
            "ledgerName": "VAT Output 5%",
            "entryType": "CREDIT",

          {
            "stockItemName": "Pure Mango Nectar 1L",
```

#### Detailed Column & Field Dictionary for Sales Vouchers:

##### Voucher Header Level:
| Field Name | Type | Mandatory | Tally XML Equivalent | Description |
| :--- | :--- | :--- | :--- | :--- |
| `guid` | String | Yes | `<GUID>` | Unique voucher identifier generated by the mobile app or cloud. |
| `voucherNumber` | String | Yes | `<VOUCHERNUMBER>` | Invoice serial number (e.g. `INV-1002`). |
| `voucherDate` | String | Yes | `<DATE>` | ISO Date string (e.g. `2026-11-14`). Format for Tally as `YYYYMMDD`. |
| `voucherType` | String | Yes | `<VOUCHERTYPENAME>` | Standard voucher type (`Sales`). |
| `partyLedgerName` | String | Yes | `<PARTYLEDGERNAME>` | Customer Ledger name in Tally (Sundry Debtor). |
| `narration` | String | No | `<NARRATION>` | Remarks and driver notes. |
| `grossAmount` | Number | Yes | Calculated | Subtotal before tax. |
| `taxAmount` | Number | Yes | Tax Ledger | VAT / GST total tax. |
| `roundOffAmount` | Number | No | RoundOff Ledger | Decimal adjustment. |
| `netAmount` | Number | Yes | Total | Total invoice invoice value. |

##### `ledgerEntries` Array (Double-Entry Balanced Ledgers):
| Field Name | Type | Description |
| :--- | :--- | :--- |
| `ledgerName` | String | Name of the ledger in Tally (Party, Sales, VAT, Discount). |
| `entryType` | String | `"DEBIT"` (`<ISDEEMEDPOSITIVE>Yes</ISDEEMEDPOSITIVE>`) or `"CREDIT"` (`<ISDEEMEDPOSITIVE>No</ISDEEMEDPOSITIVE>`). |
| `amount` | Number | Monetary amount for this ledger line. Note: In Tally XML, Debits are represented with negative values (e.g., `-75.60`). |
| `isParty` | Boolean | `true` if this ledger is the customer/debtor. |

##### `inventoryEntries` Array (Item Line Items with Godowns):
| Field Name | Type | Description |
| :--- | :--- | :--- |
| `stockItemName` | String | Exact Name of Stock Item in Tally (`<STOCKITEMNAME>`). |
| `godownName` | String | Godown / Van location name in Tally (`<GODOWNNAME>`, e.g., `Van 01 Godown`). |
| `quantity` | Number | Actual and Billed quantity (`<ACTUALQTY>`, `<BILLEDQTY>`). |
| `unit` | String | Base UOM (`<ACTUALQTY>4 Nos</ACTUALQTY>`). Default: `"Nos"`. |
| `rate` | Number | Selling price per unit (`<RATE>18.00/Nos</RATE>`). |
| `amount` | Number | Line item total (`quantity * rate`). |

## 4. Acknowledging Imported Vouchers (Tally -> Talliffy)

Once TallyPrime successfully creates the voucher in its database, the TDL script must call the **Acknowledge Endpoint** to update the voucher's sync status in Talliffy. This prevents the voucher from being downloaded repeatedly on subsequent runs.

* **Endpoint:** `POST /api/tally/AcknowledgeVouchers`
* **Headers:**
  - `Content-Type: application/json`
  - `Authorization: Bearer <TOKEN>`

#### Request Payload:
```json
{
  "vouchers": [
    {
      "voucherNumber": "INV-1002",
      "tallyGuid": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "status": "SYNCED"
    },
    {
      "voucherNumber": "REC-2004",
      "tallyGuid": "b2c3d4e5-f6a7-8901-bcde-f12345678901",
      "status": "SYNCED"
    }
  ]
}
```

#### Request Fields:
| Field | Type | Mandatory | Description |
| :--- | :--- | :--- | :--- |
| `voucherNumber` | String | Yes (or `guid`) | Invoice / Receipt number in Talliffy. |
| `tallyGuid` | String | No | The internal GUID or MasterID generated by TallyPrime. |
| `status` | String | Yes | `"SYNCED"` (or `"FAILED_VALIDATION"` if Tally rejected it). |
| `errorMessage` | String | No | Error reason if Tally rejected the voucher. |

#### Response (HTTP 200 OK):
```json
{
  "isValid": true,
  "message": "Successfully acknowledged 2 voucher(s)",
  "errorCode": null,
  "data": {
    "updatedCount": 2,
    "totalProcessed": 2
  }
}
```

## 6. Pulling Masters from Talliffy (Talliffy -> Tally)

If Tally needs to pull records that were created or edited on the road by van drivers:
* `POST /api/tally/Customers` — Returns all customer ledgers with current balances and TRN.

* `POST /api/tally/Godowns` — Returns all active godown storage locations.

## 7. Sample Implementation Snippets

### 7.1 Native TDL Code Snippet (HTTP Call & Bearer Token)

In TDL, use the `$$HTTPPostEx` or `$$HTTPPost` functions to communicate with the REST API:

```tdl
[Function: TalliffyAuthenticate]
    Variable: vUrl      : String
    Variable: vPayload  : String
    Variable: vResponse : String
    Variable: vToken    : String

    00 : Set : vUrl     : "http://66.116.232.161:8088/api/tally/Auth"
    10 : Set : vPayload : '{"userId":"tally_connector","password":"StrongPassword123!","apiKey":"VB-API-KEY-998877"}'
    
    ;; Make HTTP POST request to get Bearer Token
    20 : Set : vResponse : $$HTTPPost:##vUrl:##vPayload:"application/json"
    
    ;; Parse token from JSON response string (or store for subsequent queries)
    30 : Set : ##TalliffyGlobalToken : $$JsonGet:##vResponse:"data.token"
    40 : MsgBox: "Talliffy Status" : "Connected successfully! Token acquired."
    50 : Return

[Function: PullVanSalesInvoices]
    Variable: vUrl       : String
    Variable: vHeaders   : String
    Variable: vPayload   : String
    Variable: vXmlData   : String

    ;; Direct Tally XML Pull
    00 : Set : vUrl     : "http://66.116.232.161:8088/api/tally/export/vouchers.xml"
    10 : Set : vHeaders : "Authorization: Bearer " + ##TalliffyGlobalToken
    20 : Set : vXmlData : $$HTTPGetEx:##vUrl:##vHeaders
    
    ;; Pass directly to Tally's Import Engine
    30 : Execute: Import: ##vXmlData
    40 : Return
```

### 7.2 cURL Shell Verification Script

The TDL developer can verify the API immediately from any terminal:

```bash
# 1. Login and get JWT Bearer Token
AUTH_RESP=$(curl -s -X POST http://66.116.232.161:8088/api/tally/Auth \
  -H "Content-Type: application/json" \
  -d '{"userId":"tally_connector","password":"StrongPassword123!","apiKey":"VB-API-KEY-998877"}')

echo $AUTH_RESP

# 2. Extract Token
TOKEN=$(echo $AUTH_RESP | grep -o '"token":"[^"]*' | cut -d'"' -f4)

# 3. Pull Sales Invoices
curl -s -X POST http://66.116.232.161:8088/api/tally/SalesVouchers \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"voucherStatus":"READY"}'

# 4. Pull Receipts
curl -s -X POST http://66.116.232.161:8088/api/tally/ReceiptVouchers \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{}'

# 5. Acknowledge Imported Invoices
curl -s -X POST http://66.116.232.161:8088/api/tally/AcknowledgeVouchers \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"vouchers":[{"voucherNumber":"INV-1002","status":"SYNCED"}]}'
```

## 8. Summary Checklist for TDL Developer

1. **Host Connection:** Connect to `http://66.116.232.161:8088` (or `https://vansales.talliffy.com`).
2. **First Call:** Send `POST /api/tally/Auth` with credentials:
   - `userId`: `tally_connector`
   - `password`: `StrongPassword123!`
   - `apiKey`: `VB-API-KEY-998877`
3. **Capture Bearer Token:** Read `data.token`.
4. **Header on All Calls:** Send `Authorization: Bearer <token>`.
5. **Pull Invoices:** `POST /api/tally/SalesVouchers` (or `GET /api/tally/export/vouchers.xml`).
6. **Pull Receipts:** `POST /api/tally/ReceiptVouchers`.
7. **Post to Tally Books:** Map fields into Tally XML schema (`ALLLEDGERENTRIES.LIST` and `ALLINVENTORYENTRIES.LIST`).
8. **Acknowledge:** Send `POST /api/tally/AcknowledgeVouchers` with the imported voucher numbers to mark them `SYNCED`.
